# 质量评分与验证机制

`kb check` 只回答"数据有没有坏"；`kb score` 回答"整理得好不好"。两者互补，每次采集后都要跑。

## 一、评分四维度（每篇 0-1 分，等权平均）

### 1. 采集完整性（acquisition）

按笔记类型加权：

| 类型 | 公式 |
|---|---|
| 视频 | `0.4×有正文 + 0.5×min(ASR/200, 1) + 0.1×min(OCR/50, 1)` |
| 图文 | `0.8×有正文 + 0.2×min(OCR/50, 1)` |

设计逻辑：视频笔记的信息大头在逐字稿（通常 1500-2500 字），ASR 占一半权重——缺失时该篇会被压到 0.5 以下，一眼可见。

### 2. 归档完整性（archival）

`0.5×卡片存在 + 0.5×分类三方一致`（卡片 frontmatter = 物理目录 = notes.json；只对上一致给 0.25）。

### 3. 总结可读性（readability）

| 项 | 分值 |
|---|---|
| 一句话核心存在且 ≥15 字 | 0.25（存在但过短 0.10） |
| 核心要点 3-8 条 | 0.35（有但数量越界 0.20） |
| 行动项 ≥1 条 | 0.20 |
| 溯源段含原链接 | 0.20 |

### 4. 信息保留度（retention）

知识卡字数 / 原文总字数（正文+ASR+OCR）：

| 比例区间 | 得分 | 含义 |
|---|---|---|
| 3% – 60% | 1.0 | 正常摘要区间 |
| < 3% | 按比例×0.7 | 丢信息 |
| > 60% | 0.85 | 复述而非提炼 |
| 原文 <150 字 | 1.0 | 短笔记无丢失风险 |

## 二、等级与处置

| 等级 | 分数 | 处置 |
|---|---|---|
| A | ≥ 0.90 | 达标 |
| B | ≥ 0.75 | 达标，可关注末位几篇 |
| C | ≥ 0.60 | 逐篇检查：多半是 ASR 缺失或卡片结构不全 |
| D | < 0.60 | 必须处理：重新采集该篇 / 重写卡片 |

库级总评 = 全部笔记均分。输出自动列出最差 5 篇（`--detail` 看全量）。

## 三、验证机制（双层）

1. **一致性层（kb check，硬门槛）**：A 索引 / B 分类 / C 新鲜度 / D 资源镜像 / E 云端备份。任何一段不过都以非零退出码结束。可自动修的（card_path、frontmatter 分类）用 `kb check --fix`。
2. **效果层（kb score，软目标）**：四维评分 + 等级 + 历史趋势。不阻塞流程，但 C/D 级要列入待办。

## 四、日志与历史

- **评分历史**：每次 `kb score` 追加一行到 `logs/score_history.jsonl`（时间戳 / 篇数 / 四维均分 / 等级 / C/D 篇 note_id 清单 / notes.json 内容指纹）。可观察库质量随时间的变化，防止"越采越糟"。
- **采集原文**：`logs/collect_YYYYMMDD.txt` 是当轮点点的完整对话落盘（含"没收到附件"等异常回复），是排查采集问题的第一现场。
- **检索缓存**：`index/.kb_last.json` 记录上次检索结果顺序，供 `kb open <序号>` 使用（临时数据，不入库）。

## 五、典型低分与修复

| 症状 | 典型分数 | 修复 |
|---|---|---|
| 视频笔记 ASR 缺失 | 采集 ≈ 0.45 | 该篇单独重新发给点点整理 |
| 旧格式卡片缺段 | 总结 0.35 | 按输出标准重写卡片 |
| 卡片过短 | 保留 < 0.5 | 补要点与行动项 |
| 归档 0 分 | 卡片未写 | 补卡后 `kb rebuild` |
